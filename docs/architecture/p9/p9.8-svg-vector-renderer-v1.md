# P9.8 — SVG / Vector Topology Renderer v1

## Goal

Render topology candidates as dynamic vector previews derived from the same candidate model used by generation. SVG/vector output is presentation-only and can never become the source of canonical geometry.

## Projection chain

```text
ApartmentTopologyCandidate
        ↓
ApartmentTopologyVectorProjector
        ↓
WizardPreviewScene / apartment vector scene
        ↓
Flutter painter and/or inert SVG
```

No path exists in the reverse direction.

## Required preview semantics

Apartment preview roles must represent at least:

```text
apartmentEnvelope
habitableRoom
kitchen
wetRoom
circulation
storage
balconyOrLoggia
entry
opening
label
```

P9 may extend the P8 `WizardPreviewRole` enum or introduce a provider-neutral semantic role contract, but must not create an alternate preview transaction model.

## Card and large preview

The same candidate supports two projections:

```text
card preview: compact, labels minimized, topology comparison focus
large preview: readable room labels, area summary, warnings, selected candidate detail
```

Geometry is transformed from millimetres into normalized scene coordinates using a deterministic affine fit. Scene transforms never modify candidate geometry.

## SVG safety contract

Generated SVG is inert:

```text
no script
no event handlers
no external URLs
no foreignObject
no embedded HTML
no WebView dependency
no external fonts/images
```

Use stable `data-key`/semantic keys derived from candidate slot identity, not persistent project IDs.

## Theme contract

Preview supports native light/dark themes. Semantic meaning must not rely on color alone. Strokes, labels and room-role symbols must remain distinguishable under high-contrast and grayscale conditions.

## Accessibility

Every candidate card exposes a localized semantic summary, for example conceptually:

```text
3-room apartment, 78.5 square metres, kitchen-living, 2 bathrooms, 1 loggia, split day/night family, score 91 percent
```

The accessible label is built from typed candidate metadata, not parsed SVG text.

## Determinism

Same candidate fingerprint must produce equivalent scene element keys/order/geometry. SVG attribute order should also be stable where practical so golden tests remain useful.

## Performance gates

On the P9 reference CI environment:

```text
project vector scenes for 6 candidates: p95 <= 100 ms, p99 <= 200 ms
single card scene allocation should remain bounded
```

SVG string generation, when used, is included in this renderer budget.

## Tests

```text

apartment_svg_inertness_test.dart
apartment_preview_determinism_test.dart
apartment_preview_semantics_test.dart

```

Golden image tests may supplement but never replace semantic/vector-model tests.

## Exit gate P9-G08

```text
preview derives from candidate model
no SVG parsing into domain
card/large previews share source candidate
stable scene keys/order
inert SVG contract proven
RU/EN semantic summary available
light/dark/a11y behavior qualified
renderer performance gates pass
```
