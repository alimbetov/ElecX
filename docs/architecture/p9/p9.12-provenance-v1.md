# P9.12 — Apartment Generation Provenance v1

## Goal

Persist enough field-aware generation metadata to explain where generated apartment entities came from and to make future P15 selective regeneration possible without treating generated content as a separate project state.

## Canonical model

Recommended project-level store:

```dart
final class GenerationState {
  final Map<GenerationId, GenerationManifest> manifests;
  final Map<EntityId, EntityGenerationProvenance> entityProvenance;
}
```

This metadata is part of canonical project persistence and semantic fingerprint where relevant.

## GenerationManifest

Minimum fields:

```text
generationId
originType = wizard
discipline/scope = architectural-apartment
catalogVersion
templateId
templateVersion
generatorVersion
scoringProfileVersion
familyId
variantSeedId
normalizedIntentFingerprint
candidateFingerprint
targetProjectId
targetSiteId
targetBuildingId
targetLevelId
created entity generation keys
```

Timestamps, if stored for audit UX, are not used as determinism inputs and should be excluded from semantic-equivalence fingerprint unless explicitly under test.

## Entity provenance

Every generated Zone/Space/Opening and other selectively regenerable entity stores or references:

```text
generationId
generationKey
originType = wizard
overriddenProperties = {}
lockedFromRegeneration = false
```

`generationKey` is semantic and stable across equivalent regeneration intent, e.g.:

```text
zone:apartment
space:living
space:bedroom:1
space:bathroom:1
```

It is not a display name or entity UUID.

## Field-aware future compatibility

P9 need not implement P15 regeneration, but provenance shape must already support:

```text
PropertyKey override set
lockedFromRegeneration
baseline template/generator identity
```

A later manual edit can mark exact overridden properties rather than one coarse `userModified=true` flag.

## Persistence

GenerationState must round-trip through the project codec/repository used by the current canonical persistence path.

Required proof:

```text
Generate
→ Save
→ Close
→ Reopen
→ same manifest semantic fields
→ same entity generation keys
→ same candidate/template/family identity
```

## Versioning/migration

Projects created before P9 have empty generation state. Migration MUST NOT invent wizard provenance for legacy manual entities.

Unknown future manifest fields must follow the repository's normal schema-version/migration strategy rather than being silently discarded.

## No second state

Provenance does not contain a duplicate apartment geometry graph. It references canonical entities and records generation origin/baseline only.

Forbidden:

```text
serialized duplicate candidate as authoritative project state
SVG snapshot as regeneration authority
localized room names as generation keys
UUID-based template semantics
```

## Validation

Fail canonical validation when provenance references missing generation/entity IDs in a way that violates project integrity. Orphan handling during destructive edits must be explicit: removing generated entities updates/removes their provenance atomically with the same command.

## Exit gate P9-G12

```text
manifest persisted
family/template/seed/generator/request/candidate identity persisted
entity generation keys persisted
no duplicate geometry authority
legacy projects migrate with empty provenance
save/reopen preserves provenance
shape compatible with future field-aware P15 regeneration
```
