# P9.13 — Qualification & Golden Journey v2

Status: **AUTHORITATIVE ACCEPTANCE SPECIFICATION**  
Consumes: completed P9.1..P9.12 implementation  
Produces: merge disposition for P9

## 1. Objective

Prove that P9 is not merely feature-complete but deterministic, transaction-safe, persistent, accessible and performant as one production vertical slice.

P9 cannot be marked accepted from unit tests alone.

## 2. Acceptance dimensions

P9.13 qualifies:

```text
functional correctness
determinism

geometry integrity
ranking stability
preview/apply exactness
Undo/Redo
persistence/reopen
provenance/override tracking
RU/EN presentation
accessibility/reduced motion
performance/memory
native platform behavior
regression safety
```

## 3. Reference fixture corpus

Create a versioned test corpus with at least:

```text
room counts 1..10
areas near min/preferred/max per representative template
bathroom counts 1..3
balcony counts 0..2
kitchen modes separate/kitchenLiving/openPlan where supported
corridor modes auto/compact/central/minimal where supported
family preferences all enabled families
facade preferences representative values
```

Minimum deterministic corpus target: **>= 250 supported requests** plus **>= 100 intentionally unsupported/invalid requests**.

Corpus version is recorded in qualification evidence.

## 4. Requirement traceability

Every `P9.x-FR/INV/ERR/NFR` marked merge-blocking MUST trace to one or more tests.

Maintain a machine-readable or Markdown trace table:

```text
Requirement ID -> test file -> test name -> gate
```

No merge with undocumented untested hard requirement.

## 5. Stage contract suites

### P9.13-FR-001 — P9.1 parameter contract

Prove typed validation, normalization, canonical fingerprint and target-scope behavior.

### P9.13-FR-002 — P9.2 catalog integrity

Validate complete production catalog before candidate generation tests.

### P9.13-FR-003 — P9.3 grammar corpus

Every enabled family/seed is exercised; expansion is bounded and deterministic.

### P9.13-FR-004 — P9.4 area property suite

For supported requests:

```text
sum areas == request
all min/max respected
no residual
same result across permutations/repeats
```

### P9.13-FR-005 — P9.5 semantic suite

Inject blockers for disconnected/private-transit/wet-core/kitchen/balcony conditions and prove fail-closed behavior.

### P9.13-FR-006 — P9.6 geometry property suite

Check integer-grid, no overlap, no self-intersection, envelope containment, required boundaries/exposure and stable normalized fingerprint.

### P9.13-FR-007 — P9.7 ranking suite

Use golden fixtures with expected stable candidate ordering/score breakdown and diversity selection.

### P9.13-FR-008 — P9.8 renderer suite

Snapshot deterministic vector/SVG structure, security/inertness, RU/EN semantics and element bounds.

### P9.13-FR-009 — P9.9 provider suite

Prove target availability, selection invalidation, no session leakage and no mutation before Apply.

### P9.13-FR-010 — P9.10 P8 integration suite

Prove apartment-aware Diff, exact preview candidate, stale failure and no Apply regeneration.

### P9.13-FR-011 — P9.11 materialization suite

Prove exact entity counts, stable IDs, boundary coordinates, canonical validation, Undo/Redo.

### P9.13-FR-012 — P9.12 provenance suite

Prove manifest persistence, generation keys, override tracking and Undo/Redo consistency.

## 10. Negative journeys

### NG-01 Non-empty Level

Apartment Wizard must fail closed with `p9.provider.target-not-empty`; no diff/apply.

### NG-02 Unsupported request

No compatible candidate:

- user input preserved;
- blocking parameters/reasons shown;
- optional nearest supported suggestions are non-mutating;
- canonical state unchanged.

### NG-03 Stale preview

After preview, commit another canonical edit elsewhere. Apartment Apply must fail stale and require refresh; old reservation is not committed.

### NG-04 Cancel

Generate/select/preview/cancel. Prove fingerprint/version/Undo/repository unchanged.

### NG-05 Invalid catalog fixture

Malformed template fails catalog validation before user mutation.

### NG-06 Renderer failure injection

Preview card rendering failure cannot mutate candidate/canonical project.

### NG-07 Persistence failure injection

Atomic commit/repository failure leaves previous valid project according to existing repository transaction semantics and does not leave partial generation provenance.

## 11. Fuzz/property testing

Generate bounded valid parameter combinations from catalog constraints.

Minimum automated property sample per CI acceptance run: **>= 1,500 cases** across families/templates where runtime permits.

Properties:

```text
no exception for qualified supported request
no accepted invalid semantic graph
no overlapping accepted geometry
all coordinates bounded/grid-aligned
candidate count bounded
stable fingerprint on rerun
all generated entities owned by target Level/Zone
```

Unsupported generated cases must return typed rejection, not crash.

## 12. Hard performance gates

Reference environment is logged in CI (`uname`, CPU, memory, Flutter/Dart versions).

### P9.13-NFR-001 — Candidate pipeline

For representative request corpus, complete:

```text
P9.1 normalization
P9.2 filter
P9.3 expansion
P9.4 fit
P9.5 semantic validation
P9.6 geometry
P9.7 score/diversify
```

Hard gates:

```text
p95 <= 500 ms
p99 <= 900 ms
```

Measured after warm-up, excluding UI rendering and repository persistence.

### P9.13-NFR-002 — Vector cards

Render vector/SVG for up to 6 selected candidates:

```text
p95 <= 100 ms
p99 <= 200 ms
```

### P9.13-NFR-003 — Preview/Diff

P9 apartment Preview scene + semantic Diff:

```text
p95 <= 300 ms
p99 <= 600 ms
```

P8 global diff limits remain an upper-level guardrail.

### P9.13-NFR-004 — Reserved candidate materialization

Candidate build/validation before persistence:

```text
p95 <= 500 ms
p99 <= 900 ms
```

Apply must not include full generator rerun.

### P9.13-NFR-005 — Incremental memory

For the complete generate -> render 6 -> preview cycle:

```text
incremental RSS <= 128 MiB
```

after defined warm-up/baseline methodology.

No unbounded retention when regenerating candidate sets repeatedly; memory recovery trend must be characterized.
