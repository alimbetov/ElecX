# P9.13 — Qualification & Golden Journey v2

Status: **AUTHORITATIVE ACCEPTANCE SPECIFICATION**  
Consumes: completed P9.1..P9.12 implementation  
Produces: merge disposition for P9

## 1. Objective

Prove that P9 is deterministic, transaction-safe, physically coherent, persistent, accessible and performant as one production vertical slice.

P9 cannot be accepted from unit tests or UI screenshots alone.

## 5. Stage contract suites

### P9.13-FR-001 — P9.1 parameters

Prove typed validation, explicit area basis, kitchen-mode semantics, normalization, intent fingerprint, request/selection separation and target-scope behavior.

### P9.13-FR-002 — P9.2 catalog

Validate complete production catalog including area participation, dimensional constraints, topology references and coverage.

### P9.13-FR-003 — P9.3 grammar

Exercise every enabled family/seed; prove bounded expansion, stable semantic keys and deterministic draft fingerprints.

### P9.13-FR-004 — P9.4 area

For supported requests prove:

```text
sum(interior-participating areas) == requested interior area
appendage area excluded from interior accounting
all min/max respected
zero interior residual
same result across permutations/repeats
```

### P9.13-FR-005 — P9.5 semantics

Inject blockers for disconnected/private-transit/wet-core/kitchen/balcony/exterior-exposure conditions and prove fail-closed behavior.

### P9.13-FR-006 — P9.6 geometry

Check integer grid, no overlap/self-intersection, interior-envelope coverage, appendage attachment, dimensional constraints, required boundaries/exposure and stable fingerprint.

### P9.13-FR-007 — P9.7 ranking

Use golden fixtures with expected score breakdown, stable order, duplicate suppression and diversity selection.

### P9.13-FR-008 — P9.8 renderer

Snapshot deterministic vector/SVG structure, inertness/security, RU/EN semantics and element bounds.

### P9.13-FR-009 — P9.9 provider

Prove target availability, candidate selection invalidation, no cross-session leak and no mutation before Apply.

### P9.13-FR-010 — P9.10 P8 integration

Prove apartment-aware Diff, exact frozen preview, stale failure and no Apply regeneration.

### P9.13-FR-011 — P9.11 materialization

Prove exact entity counts/IDs, boundary coordinates, one entry opening, all required interior access openings, stable hosts, canonical validation and Undo/Redo.

### P9.13-FR-012 — P9.12 provenance

Prove manifest persistence, generation keys, candidate/request version traceability, core field override tracking and Undo/Redo consistency.

## 10. Negative journeys

### NG-01 — Non-empty Level

Fail `p9.provider.target-not-empty`; no candidate commit path.

### NG-02 — Unsupported request

No compatible candidate:

- preserve input;
- show structured blocking reasons;
- suggestions are non-mutating;
- canonical state unchanged.

### NG-03 — Stale preview

After Preview, commit another canonical edit. Apartment Apply fails stale; old reservation is not committed.

### NG-04 — Cancel

Generate/select/Preview/Cancel -> fingerprint/version/Undo/repository unchanged.

### NG-05 — Invalid catalog

Malformed template fails catalog integrity before user mutation.

### NG-06 — Renderer failure injection

Renderer failure cannot mutate candidate/canonical project.

### NG-07 — Opening host failure

Force required entry/interior opening not to fit/resolve host. Candidate must fail before commit; no “adjacency-only” apartment may be applied.

### NG-08 — Persistence failure injection

Atomic persistence failure leaves previous valid project and no partial provenance/opening state according to repository semantics.

### NG-09 — Locale switch

Switch RU/EN during candidate browsing. Request/candidate fingerprints and canonical result remain unchanged; only presentation changes.
