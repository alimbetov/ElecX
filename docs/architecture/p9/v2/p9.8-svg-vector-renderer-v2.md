# P9.8 — SVG / Vector Topology Renderer v2

Status: **READY FOR IMPLEMENTATION**  
Consumes: ranked `ApartmentGeometryCandidate`  
Produces: provider-neutral vector scene + inert SVG projection

## 1. Objective

Render each apartment candidate as a deterministic diagrammatic vector preview suitable for Wizard cards and larger preview surfaces without making rendered output authoritative.

Canonical rule:

```text
candidate geometry -> vector scene -> SVG/UI paint
```

Forbidden:

```text
SVG/UI paint -> parse -> canonical geometry
```

## 2. Renderer layers

### Layer A — ApartmentTopologyVectorScene

Provider-neutral immutable scene model derived from candidate geometry.

### Layer B — SVG projector

Serializes scene into inert SVG text.

### Layer C — Flutter/native painter

MAY render the same scene directly without parsing SVG.

No layer owns canonical project semantics.

## 3. Vector scene contract

Conceptual:

```dart
final class ApartmentTopologyVectorScene {
  final int widthUnits;
  final int heightUnits;
  final String semanticLabelKey;
  final List<ApartmentVectorElement> elements;
}
```

Element kinds:

```text
polygon
polyline
line
text-anchor metadata
entry marker
balcony/loggia marker
wet-core marker metadata
```

Display text itself SHOULD be localized outside the scene where possible; semantic keys are stable.

## 4. Coordinate normalization

### P9.8-FR-001

Renderer computes bounds from candidate geometry and maps integer-mm coordinates into a stable normalized viewBox.

Recommended card viewBox:

```text
0 0 320 220
```

with fixed logical padding.

Scale uses deterministic rational/double projection only for presentation. Candidate fingerprint does not include rendered floating coordinates.

### P9.8-FR-002

Aspect ratio is preserved. The candidate is centered within the viewBox and never stretched independently on X/Y.

## 5. Visual grammar

Required presentation roles:

```text
external boundary
internal partition
space region
space label anchor
entry marker
balcony/loggia region or marker
selected/highlight metadata
warning marker metadata
```

Colors are theme-owned presentation values, not serialized semantic state.

## 6. Space labels

Card preview SHOULD show short semantic labels only where legible.

Examples resolved by localization:

```text
Living
Bed 1
Kitchen
Bath
Hall
Loggia
```

At small card size, renderer MAY suppress text while preserving accessible semantic summary.

No canonical behavior depends on whether a label is visually rendered.

## 7. Accessibility contract

### P9.8-FR-003

Each card exposes one concise semantic description independent of SVG internals.

Example semantic content:

```text
3-room corner apartment, 78.5 square metres, kitchen-living room, 1 bathroom, 1 loggia, score 87 percent
```

The presentation layer localizes this in RU/EN.

### P9.8-FR-004

Screen readers MUST NOT be forced to navigate every wall segment as a separate accessibility node.

The card is one meaningful selectable semantic entity with optional structured summary actions.

## 8. SVG security/inertness

### P9.8-INV-001

Generated SVG MUST contain none of:

```text
<script>
on* event attributes
<foreignObject>
external URLs
image href to network/file
CSS imports
embedded executable content
```

### P9.8-INV-002

All text/attribute content is escaped.

### P9.8-INV-003

SVG output is generated only from bounded internal scene primitives.

## 9. Stable serialization

SVG elements are emitted in fixed order:

```text
1 outer envelope
2 space fills/polygons sorted by semantic key
3 internal boundaries sorted by semantic segment key
4 markers sorted by role/key
5 labels sorted by semantic key
```

Attributes use fixed ordering and normalized numeric formatting.

Equivalent scenes should produce byte-identical SVG in tests.

## 10. Element count bounds

Hard v1 bounds per card:

```text
polygons/regions <= 40
lines/polylines  <= 128
labels           <= 32
all elements     <= 256
```

Exceeding the bound fails preview generation rather than emitting pathological markup.

## 11. Light/dark theme

Scene stores semantic roles, not hard-coded color values.

Flutter/native rendering maps roles to theme tokens.

SVG MAY use `currentColor` and stable CSS classes/variables but MUST NOT encode application theme as candidate semantics.

## 12. Reduced motion

Topology cards are static by default.

Selection/transition animations MUST honor platform `disableAnimations` / reduced-motion state. Reduced motion must not change card content, ranking or layout geometry.

## 13. Comparison affordances

Vector scene MAY expose typed metadata for UI overlays:

```text
area by space
family name
score summary
wet-core count
circulation ratio
warnings
```

These overlays are presentation-only and do not alter the candidate.

## 14. Fingerprints

Renderer MAY have a `sceneFingerprint` for regression snapshots:

```text
candidate.geometryFingerprint
rendererVersion
ordered scene primitives
```

This is separate from canonical candidate fingerprint.

Changing visual-only rendering must not invalidate persisted generation provenance.

## 15. Error taxonomy

```text
p9.render.invalid-bounds
p9.render.non-finite-projection
p9.render.element-limit
p9.render.invalid-scene-key
p9.render.serialization-failure
```

No renderer failure may partially mutate Wizard/canonical state.

## 16. NFR

### P9.8-NFR-001

Generate vector scenes + SVG for 6 candidates:

```text
p95 <= 100 ms
p99 <= 200 ms
```

### P9.8-NFR-002

One card SVG SHOULD remain below 64 KiB for the v1 bounded geometry model.

### P9.8-NFR-003

Renderer requires no backend, filesystem or browser runtime.

## 17. Acceptance tests

```text
P9.8-AT-001 same geometry yields byte-identical SVG
P9.8-AT-002 SVG contains no script/event/external reference
P9.8-AT-003 special characters are escaped
P9.8-AT-004 viewBox preserves aspect ratio
P9.8-AT-005 element ordering independent of source collection order
P9.8-AT-006 card exposes RU semantic description
P9.8-AT-007 card exposes EN semantic description
P9.8-AT-008 reduced-motion state does not alter scene semantics
P9.8-AT-009 SVG is never needed to reconstruct candidate geometry
P9.8-AT-010 6-card hard p95/p99 gate passes
```

## 18. Exit gate

P9.8 is complete when one candidate model feeds both card/larger preview projections, SVG is inert/deterministic/bounded, accessibility is card-level and RU/EN capable, and no rendering artifact is treated as canonical input.
