# P9.10 — P8 Preview / Diff Integration v2

Status: **READY FOR IMPLEMENTATION**  
Consumes: exact selected P9 candidate + `ApartmentReservedProjectCommand`  
Uses: accepted P8 reserved preview/commit lifecycle

## 1. Objective

Integrate apartment generation into P8 Preview/Diff so the user sees the exact canonical candidate that will be committed, with apartment-aware semantic changes rather than generic entity IDs.

P9.10 closes audit finding **A08**.

## 2. Non-negotiable P8 contract

P9 MUST reuse:

```text
MutationIdentityReservation
ReservedProjectMutationCoordinator
ReservedProjectMutationPreview
ProjectSemanticChangeSet
LocalProjectVersion stale check
one commit -> one UndoRecord
```

P9.10 MUST NOT create:

- a second preview transaction engine;
- provider-specific repository writes;
- Apply-time regeneration;
- a “preview-only” geometry different from the candidate to be committed.

## 3. Exact-preview rule

### P9.10-INV-001

The large apartment preview is projected from:

```text
ReservedProjectMutationPreview.candidate
```

not from re-running P9.3..P9.7.

### P9.10-INV-002

Apply commits the exact frozen candidate referenced by the preview coordinator.

No template, scoring or geometry algorithm executes during Apply to replace it.

## 4. Apartment-aware Diff categories

Extend P8 diff categories to at least:

```text
site
building
level
structuralZone
space
opening
adjacency
boundaryTopology
provenance
other
```

The UI MAY group low-level categories under higher-level apartment sections.

## 5. Semantic titles

Diff MUST NOT present raw generic titles such as:

```text
SpaceId 550e8400...
ZoneId abcd...
```

when canonical candidate semantics are available.

Required examples:

```text
Apartment zone “Apartment 1”
Bedroom 1
Bedroom 2
Kitchen-living room
Bathroom
Entrance hall
Loggia
```

Localized display title is presentation; stable sort/category semantics are locale-independent.

## 6. Zone diff projection

For `ProjectStructuralZoneEntity` include:

```text
kind
name/display label
level context
space count
```

For generated apartment:

```text
Kind: apartment
Spaces: N
```

`ZoneId` is available in details/debug but is not the primary human title.

## 7. Space diff projection

For each `ProjectSpaceEntity` include at least:

```text
SpaceUsage
ProjectSpaceType
level/apartment context
planned/realized area
geometry summary
```

Geometry summary SHOULD be semantic and compact:

```text
Area: 14.2 m²
Boundary: 4 edges
Exterior exposure: qualified candidate-local exterior boundary
```

Do not dump raw polygon arrays into the default Diff UI.

## 8. Boundary topology diff

Boundary creation can be verbose. Default UX groups it under its owning Space.

Conceptually:

```text
Bedroom 1
  + Space
  + Boundary topology (4 edges)
```

Advanced/details mode MAY show individual reserved `BoundaryEdgeId`s.

A generated boundary MUST still exist in the typed semantic change set so Undo/persistence are complete even if UI groups entries.

## 9. Adjacency/opening diff

Show human relations:

```text
Bedroom 1 adjacent to Corridor
Bathroom connected to Corridor
Kitchen-living connected to Loggia
Apartment entry opening
```

Do not derive these from localized names; project using canonical `SpaceUsage` + stable semantic context.

## 10. Provenance diff

Generation provenance is displayed as one grouped informational section, not dozens of low-value field entries.

Example:

```text
Generated with Apartment Wizard
Family: splitDayNight
Template: apt-sdn-3r v2
Generator: p9-1.0.0
```

Technical fingerprints are available in details/debug, not the primary UX.

## 11. Diff ordering

Stable order:

```text
1 owning Level
2 apartment StructuralZone
3 Spaces by semantic generation key
4 adjacency/opening relationships
5 boundary topology grouped by Space
6 provenance summary
```

Within a category use locale-independent sort keys such as generation key / semantic key / typed ID fallback.

Source map/set order MUST NOT change Diff order.

## 12. Preview scene

P9 large preview uses the same canonical candidate boundaries as P9.11 materialization.

Required overlays:

```text
room regions
room semantic labels
entry marker
balcony/loggia
selected topology family
interior area summary
appendage area summary when present
warnings (if non-blocking)
```

Optional overlays:

```text
wet-core grouping
day/night zoning
score breakdown
```

They are read-only projections.

## 13. Preview/cancel behavior

### P9.10-FR-001

Opening Preview does not increment `LocalProjectVersion`.

### P9.10-FR-002

Cancel/Back from Preview:

```text
canonical fingerprint unchanged
LocalProjectVersion unchanged
Undo stack unchanged
repository unchanged
```

Candidate selection may remain in transient Wizard session if UX returns to candidate cards.

## 14. Stale preview behavior

If current canonical version changes after Preview preparation:

```text
Apply -> blocked
error = stale LocalProjectVersion
old reservation/candidate not committed
user must refresh/rebase/regenerate preview explicitly
```

P9 MUST NOT auto-apply to the new state.

## 15. Diff volume / grouping

P9 must preserve typed operations but UI can group them.

Hard rule:

- grouped presentation MUST NOT hide blocker/conflict information;
- counts MUST reconcile with underlying semantic operations;
- search/filter operates on both group title and member semantics.

## 16. Responsive Preview / Diff contract

P9.10 follows `02-p9-cross-platform-responsive-input-contract-v2.md`.

The semantic Preview and Diff artifacts are identical across form factors. Only arrangement changes.

### COMPACT

Recommended structure:

```text
[Preview | Diff] segmented control / tabs

Preview tab
  full-width interactive preview
  semantic summary
  zoom-to-fit control

Diff tab
  full semantic grouped Diff
  blockers/warnings visible

sticky Cancel / Apply
```

The user MUST be able to inspect the full semantic Diff before Apply. Mobile is not allowed to receive a reduced Diff model.

### MEDIUM

Allowed:

```text
preview with collapsible/bottom details panel
or
preview + Diff stacked region
```

### EXPANDED / LARGE

Preferred:

```text
preview canvas | persistent semantic Diff
```

with details/sidebar as width permits.

## 17. Preview viewport state

Large preview uses shared `PreviewViewportState`.

Supported operations:

```text
zoomToFit
zoomIn / zoomOut
pinch/trackpad zoom
pan
resetView
```

### P9.10-INV-003

Viewport scale/translation is non-canonical and excluded from:

```text
candidateFingerprint
reserved preview identity
semantic Diff
Apply payload
provenance
```

### P9.10-INV-004

Responsive relayout or orientation/window resize may recompute zoom-to-fit presentation, but cannot change frozen candidate or reservation.

## 18. Apply action visibility / safety

Apply/Cancel remain reachable at all supported width/height classes and text scale `2.0`.

Rules:

- compact layout may use sticky bottom action bar;
- tablet/desktop may use pane action bar;
- safe areas/IME/system insets respected;
- Apply cannot become an icon with ambiguous semantics unless accessible name/tooltip remains explicit;
- duplicate Apply activation while commit is in progress must be prevented.

## 19. Input equivalence

Preview/Diff interaction maps to common operations.

Required access paths:

```text
mouse + keyboard
keyboard-only
single-touch
multi-touch for preview zoom where available
stylus as pointer where available
```

No required Diff section or Apply action may be hover/right-click/long-press-only.

## 20. Back/system navigation

On phone/tablet system Back from Preview maps to Wizard semantic Back/Cancel-from-preview behavior, preserving candidate selection and leaving canonical state unchanged.

It MUST NOT perform Apply or discard the entire Wizard session without the same confirmation semantics used elsewhere.

## 21. Accessibility in split/compact modes

Focus/semantic order follows task order regardless of visual panes:

```text
preview summary
preview interaction controls
Diff groups / blockers
Cancel
Apply
```

Screen readers are not exposed to individual wall line segments.

When COMPACT uses tabs, switching Preview/Diff moves focus to the newly active semantic region without resetting preview/candidate state.
