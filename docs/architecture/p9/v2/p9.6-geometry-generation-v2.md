# P9.6 — Geometry Generation v2

Status: **READY FOR IMPLEMENTATION**  
Consumes: semantically validated + area-fitted topology  
Produces: validated `ApartmentGeometryCandidate`

## 1. Objective

Generate deterministic, canonical-ready apartment room geometry in integer millimetres from semantic topology and area targets.

P9.6 is a bounded rectilinear layout engine, not a universal architectural solver.

## 2. Explicit v1 geometry scope

Supported:

```text
orthogonal polygons
rectangles
L-shaped / bounded rectilinear spaces when grammar requires
shared room boundaries
single apartment envelope produced by grammar
10 mm coordinate grid
deterministic split-tree / slicing layouts
```

Not supported in P9 v1:

```text
free-form curved walls
arbitrary imported envelope fitting
constraint-solver search over unlimited arrangements
structural column optimization
window synthesis from unknown facade
furniture packing
non-orthogonal room packing
```

## 3. Coordinate contract

Canonical generation coordinates use integer millimetres.

```dart
final class GeometryPointMm {
  final int xMm;
  final int yMm;
}
```

Generation grid:

```text
GRID_MM = 10
```

Every generated coordinate MUST be a multiple of `GRID_MM`.

## 4. Candidate model

```dart
final class ApartmentGeometryCandidate {
  final ApartmentTopologyIdentity topologyIdentity;
  final RectilinearPolygonMm envelope;
  final List<GeneratedSpaceGeometry> spaces;
  final List<GeneratedSharedBoundary> sharedBoundaries;
  final List<GeneratedExteriorBoundary> exteriorBoundaries;
  final List<OpeningIntent> openingIntents;
  final GeometryValidationReport validation;
  final String geometryFingerprint;
}
```

`GeneratedSpaceGeometry` is keyed by semantic space key, not canonical `SpaceId`.

## 5. Envelope

P9 v1 grammar creates or selects a bounded normalized apartment envelope.

The envelope MUST be:

- closed;
- rectilinear;
- non-self-intersecting;
- positive area;
- on the generation grid;
- large enough for all space minima.

No candidate may silently exceed the envelope.

## 6. Layout strategy

Preferred v1 implementation is a deterministic slicing/split tree.

Conceptually:

```dart
sealed class LayoutNode {}
final class LayoutLeaf extends LayoutNode { semanticKey }
final class LayoutSplit extends LayoutNode {
  axis: horizontal | vertical
  ratioBp: int
  first: LayoutNode
  second: LayoutNode
}
```

Grammar/variant seed provides the split skeleton and stable ordering. P9.6 resolves actual dimensions from fitted areas and aspect constraints.

## 7. Functional requirements

### P9.6-FR-001 — Deterministic grid layout

Same normalized topology/area/split skeleton produces byte-equivalent ordered coordinates.

### P9.6-FR-002 — Area realization tolerance

For each space, realized polygon area must satisfy:

```text
abs(realizedArea - fittedArea) <= max(0.5%, 0.20 m²)
```

and stay inside template min/max area constraints.

If geometry cannot realize area within tolerance, reject the candidate; do not alter fitted semantics silently.

### P9.6-FR-003 — Aspect ratio limits

Each `TopologySpaceSpec` MAY declare:

```text
minAspectBp
maxAspectBp
preferredAspectBp
```

A hard aspect limit violation rejects geometry. Preferred aspect deviation becomes a P9.7 metric.

### P9.6-FR-004 — No overlap

Interior area intersection between distinct spaces MUST be zero.

Shared boundary length is allowed; shared interior area is not.

### P9.6-FR-005 — Envelope coverage

Apartment interior coverage MUST equal the union of generated interior spaces within a documented tolerance.

Unassigned gaps larger than one grid cell are forbidden unless explicitly modeled as a semantic circulation/void space.

### P9.6-FR-006 — Shared boundary realization

Every semantic `required directBoundary` relation from P9.5 MUST have positive shared boundary length meeting any declared minimum.

### P9.6-FR-007 — Forbidden adjacency realization

If P9.5 declares a geometrically forbidden direct boundary, generated spaces MUST NOT share a positive-length interior boundary.

### P9.6-FR-008 — Exterior exposure

Every space requiring exterior exposure must own at least one segment on the apartment envelope of minimum qualified length.

Default minimum exposed segment for v1 fixtures: `600 mm`, overrideable by template.

### P9.6-FR-009 — Entry intent

Exactly one primary apartment entry boundary intent is produced and anchored to an exterior/envelope segment or explicit building-circulation interface.

### P9.6-FR-010 — Wet-core compactness geometry

For spaces in the same wet-core group, geometric compactness is measured by shared boundary or centroid/boundary distance. Template policy defines the hard maximum separation.

P9.6 emits metrics; hard policy violation rejects the candidate.

## 8. Polygon normalization

Before fingerprint/validation:

1. remove duplicate consecutive points;
2. remove zero-length edges;
3. collapse collinear intermediate vertices when identity is not yet canonical;
4. enforce one winding convention, e.g. clockwise;
5. rotate vertex sequence to stable lexicographically smallest starting vertex;
6. verify closure semantically without duplicating first point unless the polygon type requires it.

This guarantees equivalent polygons serialize identically.

## 9. Shared boundary derivation

Shared boundaries are computed from normalized polygon segments using exact integer geometry.

Do not use pixel/raster collision detection.

For two collinear opposite-facing segments, intersect integer intervals and produce a shared segment when overlap length > 0.

## 10. Canonical P7 handoff

P9.6 does not allocate `BoundaryEdgeId` while browsing cards.

It outputs semantic boundary descriptions that P9.11 materializes using P8 reservation:

```text
spaceSemanticKey
ordered normalized segments
boundary role
adjacent semantic key?
exterior role?
entry/opening intent?
```

At reservation/materialization time:

```text
semantic segment -> reserved BoundaryEdgeId -> SpaceBoundaryTopology
```

## 11. Geometry fingerprint

Includes:

```text
areaFitFingerprint
envelope normalized points
for each semantic space in stable-key order:
  normalized polygon points
shared-boundary semantic pairs/segments
exterior-exposure roles
entry intent
geometryAlgorithmVersion
```

No SVG or Flutter coordinates participate.

## 12. Geometry invariants

### P9.6-INV-001

Every polygon is closed by topology, positive-area, rectilinear and non-self-intersecting.

### P9.6-INV-002

All coordinates are integer mm on `GRID_MM`.

### P9.6-INV-003

All space polygons lie inside envelope.

### P9.6-INV-004

No two spaces overlap in area.

### P9.6-INV-005

Required semantic adjacency is geometrically realized.

### P9.6-INV-006

Required exterior exposure is realized.

### P9.6-INV-007

Equivalent normalized geometry yields identical fingerprint independent of vertex input rotation/order.

### P9.6-INV-008

Geometry generation never reads screen size, device pixel ratio or theme.

## 14. Complexity bounds

Hard v1 limits:

```text
spaces per apartment             <= 32
vertices per space after normalize <= 16
raw candidates entering P9.6    <= 64
valid candidates retained       bounded downstream
```

Any candidate exceeding these is rejected as unsupported rather than causing unbounded search.

## 15. NFR

### P9.6-NFR-001

One candidate geometry generation + validation p95 <= 20 ms, p99 <= 40 ms.

### P9.6-NFR-002

Full raw candidate batch <= 64: p99 <= 350 ms before scoring on reference CI hardware.

### P9.6-NFR-003

No floating-point equality controls topology validity.

### P9.6-NFR-004

Memory usage must remain bounded by candidate count and geometry size; no retained intermediate search tree after candidate completion.
