# P9.6 — Geometry Generation v2

Status: **READY FOR IMPLEMENTATION**  
Consumes: semantically validated + area-fitted topology  
Produces: validated `ApartmentGeometryCandidate`

## 1. Objective

Generate deterministic, canonical-ready apartment geometry in integer millimetres from semantic topology and area targets.

P9.6 is a bounded rectilinear layout engine, not a universal architectural solver and not a building-envelope fitting engine.

## 2. Explicit v1 geometry scope

Supported:

```text
orthogonal polygons
rectangles
bounded L-shaped/rectilinear spaces
shared room boundaries
one interior apartment envelope
attached balcony/loggia appendage polygons
10 mm coordinate grid
deterministic split-tree/slicing layouts
```

Not supported:

```text
curved walls
arbitrary imported-envelope fitting
unbounded constraint search
structural column optimization
automatic real facade/window synthesis
furniture packing
non-orthogonal packing
```

## 3. Coordinate contract

Canonical generation coordinates are integer millimetres.

```dart
final class GeometryPointMm {
  final int xMm;
  final int yMm;
}
```

Generation grid:

```text
GRID_MM = 10
```

Every generated coordinate MUST be a multiple of `GRID_MM`.

## 4. Candidate model

```dart
final class ApartmentGeometryCandidate {
  final ApartmentTopologyIdentity topologyIdentity;
  final RectilinearPolygonMm interiorEnvelope;
  final List<GeneratedSpaceGeometry> interiorSpaces;
  final List<GeneratedSpaceGeometry> exteriorAppendages;
  final List<GeneratedSharedBoundary> sharedBoundaries;
  final List<GeneratedExteriorBoundary> exteriorBoundaries;
  final List<OpeningIntent> openingIntents;
  final GeometryMetrics metrics;
  final GeometryValidationReport validation;
  final String geometryFingerprint;
}
```

`GeneratedSpaceGeometry` is keyed by semantic space key, not canonical `SpaceId`.

## 5. Interior envelope vs appendages

### P9.6-FR-001 — Interior envelope

`interiorEnvelope` contains exactly spaces whose P9.2 participation is `requestedInteriorArea`.

The union of accepted interior spaces must cover the interior envelope within the explicit grid tolerance.

### P9.6-FR-002 — Exterior appendages

Balcony/loggia/terrace polygons:

- do not consume `interiorEnvelope` area;
- lie outside or on the boundary of the interior envelope;
- share a positive attachment boundary with their declared host space/envelope edge;
- may not overlap interior spaces except on the shared boundary;
- may not overlap each other in area unless a future typed policy explicitly allows it.

The overall candidate bounds are derived for rendering only and are not the requested-area authority.

## 6. Envelope validity

The interior envelope MUST be:

- closed;
- rectilinear;
- non-self-intersecting;
- positive area;
- on the generation grid;
- large enough for all interior space minima/dimensions.

No interior space may silently extend beyond it.

## 7. Layout strategy

Preferred v1 implementation is a deterministic slicing/split tree.

```dart
sealed class LayoutNode {}
final class LayoutLeaf extends LayoutNode { semanticKey }
final class LayoutSplit extends LayoutNode {
  axis: horizontal | vertical
  ratioBp: int
  first: LayoutNode
  second: LayoutNode
}
```

Grammar/seed provides split skeleton and stable ordering. P9.6 resolves dimensions from P9.4 fitted areas plus P9.2 geometry constraints.

## 8. Functional requirements

### P9.6-FR-003 — Deterministic grid layout

Same normalized topology/area/split skeleton produces byte-equivalent normalized coordinates.

### P9.6-FR-004 — Area realization tolerance

For each space:

```text
abs(realizedArea - fittedArea) <= max(0.5%, 0.20 m²)
```

and realized area remains within template min/max.

Interior total area is compared to `requestedInteriorAreaDm2`; appendage area is compared only to its own fitted appendage target.

If geometry cannot realize an area within tolerance, reject; do not silently change fitted semantics.

### P9.6-FR-005 — Dimensional limits

Every space MUST satisfy P9.2 `TopologySpaceGeometryConstraints`:

```text
minShortSideMm
minLongSideMm when specified
minAspectBp <= realizedAspect <= maxAspectBp
maxVertices
```

These are product generation constraints, not statutory compliance claims.

### P9.6-FR-006 — No overlap

Area intersection between distinct spaces is zero, except shared boundaries of zero area.

### P9.6-FR-007 — Interior coverage

Union of interior spaces covers the interior envelope. Unassigned gaps larger than one generation grid cell are forbidden unless explicitly modeled as a semantic interior space.

Appendages are excluded from this coverage equation.

### P9.6-FR-008 — Required boundary realization

Every P9.5 `required directBoundary` relation has positive shared boundary length meeting template minimums.

### P9.6-FR-009 — Forbidden adjacency realization

A P9.5 geometrically forbidden direct boundary may not have positive shared length.

### P9.6-FR-010 — Exterior exposure

Every `requiresExteriorExposure` interior space owns at least one qualified segment on `interiorEnvelope` not fully consumed by an appendage attachment.

Minimum exposure comes from P9.2 geometry constraints/template default.

### P9.6-FR-011 — Candidate-local exposure preference

P9.1 exterior exposure preference is evaluated against the **candidate-local interior envelope**:

```text
oneSide
corner
oppositeSides
```

This does not claim actual Building north/east/south/west facade orientation.

### P9.6-FR-012 — Entry intent

Exactly one primary apartment entry intent is anchored to an interior-envelope segment or explicit building-circulation interface semantic side.

Entry intent cannot be hosted only on an exterior appendage.

### P9.6-FR-013 — Balcony/loggia attachment

Each exterior appendage has one declared primary attachment host and minimum shared attachment length from template policy.

### P9.6-FR-014 — Wet-core compactness

Spaces in one wet-core group are evaluated by exact shared-boundary/distance metrics. Template policy defines hard maximum separation; violations reject.

## 9. Polygon normalization

Before fingerprint/validation:

1. remove duplicate consecutive points;
2. remove zero-length edges;
3. collapse collinear intermediate vertices while no canonical edge identity exists;
4. enforce one winding convention;
5. rotate sequence to lexicographically smallest stable starting vertex;
6. verify closure semantically.

Equivalent polygons therefore serialize identically.

## 10. Shared boundary derivation

Use exact integer segment geometry, never raster/pixel collision.

For collinear opposite-facing segments, intersect integer intervals; positive overlap becomes a shared segment.

This same algorithm handles interior-space adjacency and appendage attachment.

## 11. Area conversion

```text
1 dm² = 10,000 mm²
```

Realized polygon area is computed in integer mm² using a deterministic polygon-area algorithm. Comparisons to P9.4 targets convert using integer arithmetic/rational comparison before tolerance calculation.

Floating-point display conversion is non-authoritative.

## 12. P7 handoff

P9.6 allocates no `BoundaryEdgeId` while browsing candidates.

It outputs semantic segment descriptions:

```text
spaceSemanticKey
ordered normalized segments
boundary role
adjacent semantic key?
interior-envelope/exterior-appendage role
entry/opening intent?
```

P9.11 maps these to reserved `BoundaryEdgeId` and `SpaceBoundaryTopology`.

## 13. Geometry fingerprint

Includes:

```text
areaFitFingerprint
normalized interiorEnvelope
ordered interior spaces + polygons
ordered exterior appendages + polygons
shared boundary semantic pairs/segments
exterior exposure roles
entry intent
geometryAlgorithmVersion
```

No SVG, locale or Flutter coordinates participate.

## 14. Geometry invariants

### P9.6-INV-001

Every polygon is positive-area, rectilinear, normalized and non-self-intersecting.

### P9.6-INV-002

All coordinates are integer mm on `GRID_MM`.

### P9.6-INV-003

All interior spaces lie inside `interiorEnvelope`.

### P9.6-INV-004

Exterior appendages do not consume requested interior area and do not overlap interior area.

### P9.6-INV-005

No distinct spaces overlap in area.

### P9.6-INV-006

Required semantic adjacency is geometrically realized.

### P9.6-INV-007

Required exterior exposure is realized.

### P9.6-INV-008

All hard dimensional constraints are satisfied.

### P9.6-INV-009

Equivalent normalized geometry yields identical fingerprint independent of input vertex rotation/order.

### P9.6-INV-010

Generation never reads screen size, pixel ratio, theme or locale.

## 16. Complexity bounds

Hard v1 limits:

```text
all spaces including appendages <= 32
vertices per space after normalize <= 16
raw candidates entering P9.6 <= 64
```

Exceeding bounds fails unsupported rather than triggering unbounded search.

## 17. NFR

### P9.6-NFR-001

One candidate generation + validation:

```text
p95 <= 20 ms
p99 <= 40 ms
```

### P9.6-NFR-002

Full <=64 raw candidate batch p99 <= 350 ms before scoring.

### P9.6-NFR-003

No floating-point equality controls topology validity.

### P9.6-NFR-004

Memory bounded by candidate count/geometry; no retained intermediate search tree after completion.
