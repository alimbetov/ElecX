# P9.7 — Candidate Scoring and Ranking v1

## Goal

Rank only valid candidates using a transparent deterministic product-quality score. Scoring is for Wizard recommendation order; it is not a safety or regulatory compliance score.

## Preconditions

A candidate reaches scoring only after:

```text
parameter validation
catalog compatibility
area fitting
semantic adjacency validation
wet-core validation
geometry validation
```

Any blocker means the candidate is excluded, not assigned a low score.

## Score representation

Use integer basis points:

```text
0..10000
```

No floating-point ranking authority.

## Versioned scoring profile

Recommended v1 weights:

| Metric | Weight |
|---|---:|
| areaMatch | 1600 |
| circulationEfficiency | 1400 |
| corridorEfficiency | 1000 |
| wetCoreCompactness | 1200 |
| roomAspectQuality | 1200 |
| privacySeparation | 1000 |
| kitchenModeMatch | 800 |
| balconyAttachmentQuality | 600 |
| familyPreferenceMatch | 600 |
| facadePreferenceMatch | 600 |
| **Total** | **10000** |

Weights belong to a versioned `ApartmentScoringProfile`; changing them changes ranking semantics and must bump the scoring/generator version used in provenance.

## Metric requirements

Each metric returns integer `0..10000` quality before weight multiplication. Formulae must be monotonic and documented.

Examples:

```text
areaMatch: geometric area error vs requested area
circulationEfficiency: reachable circulation area / total interior area
corridorEfficiency: penalize excessive dedicated corridor area
wetCoreCompactness: graph/geometry compactness of declared wet members
roomAspectQuality: distance from template preferred aspect ranges
privacySeparation: day/night graph separation quality
kitchenModeMatch: exact requested semantic mode
balconyAttachmentQuality: eligible exterior attachment and preferred room relation
familyPreferenceMatch: exact explicit family preference
facadePreferenceMatch: requested facade contacts satisfied
```

## Total score

Use integer arithmetic with defined rounding. Example:

```text
weighted = sum(metricScore * weight)
score = roundHalfUp(weighted / 10000)
```

The exact rounding function must be unit-tested.

## Tie-breaking

When total scores are equal:

```text
1. fewer warnings
2. lower geometric area error
3. family stable rank
4. templateId
5. templateVersion
6. seedId
7. candidateFingerprint
```

Never depend on generation/list iteration order.

## Diversity selection

Return `3..6` candidates when enough valid results exist.

Selection policy:

```text
sort all valid candidates by deterministic ranking
first pass: best candidate from each available family
second pass: fill remaining slots by global ranking
max 2 candidates per family while >=3 families are available
```

If fewer than three families are compatible, fill from available families without fabricating diversity.

## Recommendation labels

UI labels such as `Recommended` are projections of rank. They are not persisted canonical semantics.

## Exit gate P9-G07

```text
only valid candidates scored
integer score 0..10000
weights versioned
all metrics documented
stable tie-break chain
diversity deterministic
score never represented as normative compliance
```
