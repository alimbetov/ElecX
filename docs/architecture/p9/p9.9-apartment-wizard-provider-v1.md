# P9.9 — ApartmentWizardProvider v1

## Goal

Plug the apartment generator into the accepted P8 provider registry and reserved mutation lifecycle without changing P8 transaction semantics.

## Provider contract

```dart
final class ApartmentWizardProvider
    extends TypedWizardProvider<ApartmentWizardParameters> {
  final ApartmentTopologyGenerator generator;
  final ApartmentTopologyCatalog catalog;
  final ApartmentCandidateMaterializer materializer;
}
```

P9 v1 supports `LevelWizardTarget` as the canonical insertion scope.

## Target rule

P9 v1 generates one apartment into an empty target Level. A level is eligible when it has no existing canonical spaces or structural zones that would geometrically conflict with generated content.

If the level is not empty:

```text
p9.target.level-not-empty
```

is a blocker. P9 does not guess a free placement region or overlay generated geometry.

Multi-apartment floor composition belongs to P10 building/residential-complex generation, which may orchestrate multiple P9 topology results with explicit placement frames.

## Candidate discovery lifecycle

The UI/application draft controller calls the pure apartment generator before P8 canonical preview:

```text
parameters without selection
→ normalize/validate
→ generate ranked ApartmentTopologyCandidate[]
→ user selects candidate
→ selectedCandidateKey stored in typed draft parameters
```

`selectedCandidateKey` is a deterministic key derived from request/catalog/template/seed/candidate fingerprint. It is not a persistent entity ID.

## Provider generateTyped()

When P8 asks the provider to create a `ReservedProjectCommand`:

```text
1. validate target and parameters
2. deterministically regenerate/resolve candidate set for normalized request
3. resolve exact selectedCandidateKey
4. fail if missing/stale
5. construct ApplyApartmentCandidateCommand containing immutable selected candidate payload/fingerprint
```

This regeneration occurs before the P8 reserved preview is frozen. Once P8 preview exists, Apply commits that exact frozen canonical candidate and never reruns P9 generation.

## Candidate service

Recommended separation:

```text
ApartmentTopologyGenerator       pure domain/application generation
ApartmentCandidateQueryService   cache/ranking orchestration for cards
ApartmentWizardProvider          P8 adapter
ApplyApartmentCandidateCommand   reserved canonical mutation
```

The provider MUST NOT own Flutter state.

## Registry descriptor

Descriptor includes stable values:

```text
familyId          apartment
templateId        provider-level apartment generator descriptor
templateVersion   provider contract version
generatorVersion  P9 generator version
supportedScopes   { level }
```

Individual selected topology template identity belongs to candidate/provenance, not the provider descriptor.

## Error mapping

Typed failures include:

```text
unsupportedTarget
levelNotEmpty
invalidParameters
noCompatibleTemplate
noValidCandidate
candidateSelectionMissing
candidateSelectionStale
candidateBlocked
```

Raw `StateError` is not the UI-facing primary contract.

## Cache behavior

Candidate query cache may use normalized request fingerprint + catalog/generator version. It must be discardable and must not allocate/reserve project IDs.

```text

Apply never regenerates

```
