# P9.3 — Topology Families and Grammars v1

## Goal

Define apartment families as semantic generation grammars rather than fixed drawings. A family establishes spatial relationships and layout strategy; P9.6 converts the grammar into deterministic geometry.

## Canonical families

```text
compact
linear
corner
centralCorridor
corridorSpine
euro
openPlan
splitDayNight
```

These are product categories, not normative certification labels.

## Initial support envelope

| Family | Habitable rooms | Primary intent |
|---|---:|---|
| compact | 1..3 | minimum circulation, compact service core |
| linear | 1..4 | sequential facade-oriented arrangement |
| corner | 2..5 | two-side facade potential / turning plan |
| centralCorridor | 3..8 | rooms around central circulation |
| corridorSpine | 4..10 | larger apartment around longitudinal spine |
| euro | 1..4 | kitchen-living dominant day zone |
| openPlan | 1..3 | minimized day-zone separation |
| splitDayNight | 3..10 | explicit public/private zoning |

Templates may narrow these ranges.

## Grammar output

final class ApartmentTopologyDraft {
  final ApartmentTopologyFamilyId familyId;

Draft identities are template-local slot keys. No persistent IDs are allocated here.

## Family semantics

### compact
Short circulation path, compact service core, no dedicated long corridor.

### linear
One dominant sequence axis; rooms ordered along a circulation line; wet/service spaces grouped.

### corner
Two perpendicular layout bands; habitable spaces use both bands; transition belongs to circulation/day zone.

### centralCorridor
Central circulation node/path; rooms attach to it; service core reachable without passing through bedrooms.

### corridorSpine
Primary longitudinal circulation spine; room groups branch from it; spine area penalized in scoring.

### euro
`kitchenLiving` required; combined day zone is dominant public space.

### openPlan
Open day zone with minimum partitions; service/wet rooms remain explicit enclosed spaces.

### splitDayNight
Public/day cluster and private/night cluster separated by circulation; entry never requires traversal through a private bedroom.

## Variant seeds

Bounded deterministic transforms:

```text
base
mirrorX
mirrorY
entryLeft
entryRight
wetCoreNearEntry
wetCoreCentral
livingFacadePrimary
```

Stable identity:

```text
<family>/<template>/<semantic-variant-name>
```

Forbidden: random shuffle, current-time seed, platform-dependent enumeration, arbitrary permutations and silent requested-space changes.

Hard recommended seed cap:

```text
<= 12 seeds per template
```

## Determinism

Same normalized request + catalog/template version + seed + generator version produces equivalent semantic draft.
