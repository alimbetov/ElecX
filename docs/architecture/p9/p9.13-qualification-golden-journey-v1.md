# P9.13 — Qualification and Golden Journey v1

## Goal

Prove P9 as a deterministic production vertical slice rather than a visual demo. Qualification covers domain correctness, P8 lifecycle invariants, performance, accessibility, persistence and reproducibility.

## Test layers

```text
L1 value-object / parameter tests
L2 catalog schema/compatibility tests
L3 grammar golden semantic tests
L4 area-fitting/property tests
L5 adjacency/wet-core tests
L6 geometry/property tests
L7 scoring/ranking tests
L8 vector/SVG tests
L9 provider/reservation tests
L10 preview/diff tests
L11 canonical materialization/provenance tests
L12 end-to-end Golden Journey
```

## Mandatory scenario matrix

At minimum cover:

```text
room counts: 1,2,3,4,5,8,10
areas: lower-supported, nominal, upper-supported per template fixtures
kitchen: separate, kitchenLiving, openPlan where supported
corridor: auto, compact, central, minimal where supported
bathrooms: 1 and multi-bathroom
balcony: 0 and >=1
families: every canonical family at least one accepted fixture
unsupported combinations: explicit blockers
```

Use pairwise/boundary coverage rather than an unbounded Cartesian product, plus dedicated family golden fixtures.

## Determinism qualification

For fixed fixtures, repeat generation multiple times and prove identical:

```text
normalized request fingerprint
compatible template order
semantic draft fingerprint
area allocation fingerprint
geometry fingerprint
candidate fingerprint
score/rank order
vector-scene semantic keys
```

No runtime random seed is permitted.

## Cross-platform determinism

Integer/rational algorithms are chosen so fixture fingerprints are equivalent on supported native platforms. P9 merge CI must at least prove Linux + macOS where existing workflows support them; P17 later owns full native-platform qualification.

## Performance gates

Reference environment is recorded in CI logs.

Hard P9 gates:

```text
generate/rank up to 6 candidates:
  p95 <= 500 ms
  p99 <= 900 ms

vector/SVG projection for 6 candidates:
  p95 <= 100 ms
  p99 <= 200 ms

additional RSS attributable to one P9 candidate session:
  <= 128 MiB
```

P8 inherited gates remain in force, including semantic diff and Wizard interaction budgets.

Performance tests use warmups, enough samples for meaningful p95/p99 and `--concurrency=1` where measurement isolation is required.

## Accessibility / i18n

Required RU/EN matrix:

```text
candidate cards semantic labels
parameter labels/errors
unsupported-combination explanation
preview/diff labels
screen-reader traversal
text scale 100%, 130%, 200%
compact/medium/expanded widths
reduced-motion behavior
48dp minimum interactive targets where applicable
```

No candidate/family semantics depend on translated labels.

## Persistence qualification

Prove:

```text
Apply candidate
→ capture AFTER fingerprint + provenance
→ Save
→ Close
→ Reopen
→ same AFTER semantic fingerprint
→ same generation manifest semantic fingerprint
```

## Undo/Redo qualification

```text
BEFORE fingerprint
→ Apply
→ AFTER fingerprint
→ Undo
→ exactly BEFORE
→ Redo
→ exactly AFTER
```

IDs after Redo must match the original Apply result.

## Failure/fault scenarios

At minimum:

```text
no compatible template
all seeds geometrically invalid
stale selectedCandidateKey
stale LocalProjectVersion before Apply
reservation collision/invalid reservation
candidate validator failure
persistence failure after canonical commit follows existing P8 persistence policy
cancel from every Wizard step
repeat/double Apply rejected
```

## Golden Journey

Mandatory production journey:

```text
Project Hub
→ New Project
→ Create with Wizard / Basic Building
→ create/select empty Level
→ Apartment Wizard
→ enter 3-room / explicit area / kitchen / bathroom / balcony preferences
→ Generate
→ receive deterministic 3..6 ranked candidates
→ inspect dynamic vector cards
→ select candidate
→ open P8 large Preview
→ inspect apartment-aware semantic Diff
→ Apply
→ verify one canonical ProjectChangeSet + one UndoRecord
→ Undo and verify BEFORE fingerprint
→ Redo and verify exact AFTER IDs/fingerprint
→ Save
→ Close
→ Reopen
→ verify AFTER fingerprint + provenance
→ manually edit one generated room through normal authoring command
→ Save / Reopen and verify edit persists
```
