## 1. Задача и принцип

При выделении компонента в инженерном плане автоматически появляются **размерные линии**, **выносные линии**, **стрелки** и **размерный текст в рамке** от реальных границ компонента до ограничивающих стен помещения. При отмене выделения линии плавно затухают. Пока оператор удерживает общую кнопку **Distance**, последний валидный набор динамических размеров остаётся видимым; после отпускания запускается более медленное затухание.

Это только временный CAD presentation overlay. Расстояния должны вычисляться в **миллиметрах модели**, а не из экранных пикселей. Overlay не изменяет проект, инженерный граф, монтажную поверхность, маршруты, undo/redo, сохранение или авторство технических данных.

### UX-приоритеты
- Нельзя ухудшить **drag устройства, выбор портов, ручную трассировку, waypoint editing, pan/zoom и контекстные действия**.
- Максимум четыре направленных размерных направления на прямоугольной/ортогональной планировке: влево, вправо, вверх, вниз, **только если направления геометрически определены**.
- Объект на стене: расстояние до стены размещения равно нулю/касанию; **не рисовать бессмысленную нулевую размерную линию**. Показывать остальные корректные измерения.
- Объект в нише, коридоре, сложной/вогнутой комнате: использовать **первое достоверное пересечение** с реальной границей внутри соответствующего помещения, не с произвольным bbox квартиры.
- Не заявлять соответствие ГОСТ без проверки конкретной редакции стандарта и правил оформления. Использовать инженерную CAD-терминологию.

## 3. Семантика измерения

### 3.1 Геометрия
1. Источник: выбранный `ElectricalComponentPlacement` (или совместимый зарегистрированный component) и реальная граница его footprint в координатах плана.
2. Хозяин: помещение `EngineeringSpace`, содержащее выбранный объект/его host; измерения не перескакивают через стену в чужую комнату.
3. Цель: соответствующий участок внутренней границы помещения, найденный лучом из наружной опорной точки габарита по оси измерения.
4. Для ортогональных помещений: четыре осевых кандидата `-X,+X,-Y,+Y`. Для непараллельных стен: расстояние измеряется **вдоль отображённой линии**, а не ошибочно выдаётся за нормальное кратчайшее расстояние.
5. Нормальное расстояние до конкретной стены — отдельный режим и НЕ смешивается с осевыми направляющими. Не рисовать наклонную линию, подписанную величиной другой проекции.
6. Поддерживать rotation/локальную координатную систему: считать в согласованной системе координат world/plan, документировать интерпретацию направлений; не использовать screen-left/right при повороте камеры как геометрические оси.
7. Для выпуклых/вогнутых полигонов брать ближайшее положительное валидное пересечение по лучу, учитывая коллинеарность, попадание в вершину и tolerance.
8. Расстояние от **габарита** до стены, не от центра. Если геометрия корпуса неизвестна — отдельно указать режим от anchor и не показывать ложную точность.
9. Не допускать отрицательных размеров и чисел при выходе footprint за границу: показать ограниченное пояснение `Размер недоступен` / invalid geometry без ложной линии.
10. Использовать миллиметры, округление **только для текста**. Хранить и вычислять геометрию без округления измерений до форматирования.

### 3.2 Препятствия и смысл
- Стена/граница комнаты — цель размера; **дверной проём не превращается в «стену»**. Если направление достигает проёма, не выводить без проверки неправильное расстояние до непрерывной стены.
- Для дверей, окон, колонн, межкомнатных перегородок и других объектов предусмотреть явную политику: P0 измерение до границы помещения; P1 расширение targets только после отдельного согласования.
- Если по лучу существуют неоднозначные границы или цель не установлена — скрыть конкретное направление, остальные показывать.
- При перетаскивании показывать **preview** текущих расстояний только при валидной preview-геометрии; invalid preview пометить отдельно, не пересохранять и не использовать для фиксации размеров.

### 3.3 Пример
Розетка занимает по оси X участок 3600..3800 мм, левая стена x=1000 мм; **левый размер = 2600 мм**, не 2700 мм от центра. Это иллюстрация, а не fixture реального проекта.

## 4. Состояния и поведение

Использовать отдельный ephemeral state-controller / coordinator:

`hidden → appearing → visible → deselectPending → fading → hidden`

Переходы:
- **Select:** построить направляющие, fade-in ~120–180 ms.
- **Move/drag selected:** обновлять геометрию в реальном времени без нового таймера на каждый pointer-move; не ломать drag.
- **Deselect:** заморозить последний валидный измерительный snapshot, запустить задержку ~200 ms, затем fade-out ~350 ms.
- **Distance pointer DOWN:** пометить `held=true` и отменить fade; удерживать последний валидный набор, даже если выбор снят. Выход курсора с кнопки **не снимает** hold, пока не произошёл up/cancel.
- **Distance pointer UP / CANCEL:** `held=false`; если нет выделенного объекта, delayed fade ~150 ms + fade-out ~700 ms. Если объект всё ещё выделен, линии продолжают быть видимыми без затухания.
- **Клавиатура:** при focus на Distance использовать `Space` key down/up с той же семантикой, без системного «залипания». Обязательно обработать focus loss, app deactivation, pointer cancel, widget dispose, project switch, чтобы hold никогда не оставался навсегда.
- **Новый selected component во время fading:** отменить старую анимацию и показать новое измерение без двойного overlay.
- **Project/space/level change:** немедленно скрыть устаревший snapshot; держать размеры другого проекта запрещено.
- **Pan/zoom:** проектировать заново **экранную геометрию** snapshot по актуальной камере, измерения в мм не пересчитывать от пикселей.
- **Reduced motion:** без анимации / прямое переключение, удержание работает.
- **Accessibility:** у кнопки доступные имя, роль, статус удержания. Keyboard repeat не приводит к многократному переключению.

### Timing-конфигурация

| Параметр | Стартовое значение | Требования |
|---|---:|---|
| fadeIn | 150 ms | 0–500 |
| deselectDelay | 200 ms | 0–1500 |
| deselectFade | 350 ms | 0–2000 |
| holdReleaseDelay | 150 ms | 0–1500 |
| holdReleaseFade | 700 ms | 0–3000 |

Константы в одном UI config / theme extension, **не в доменной модели**. Значения доступно настраивать в конфигурации UX без миграции проекта; пользовательский редактор настроек вне P0.

- Кнопка может иметь активное состояние только пока удерживается, не сохраняется между перезапусками.
- При касании/на мобильной компоновке обеспечить семантику hold (long press не обязателен); desktop mouse и keyboard — обязательны.

## 6. Отрисовка

- Основание: `CadDimensionPainter.drawLinear` или совместимая расширенная сигнатура.
- Размерная линия со стрелками; выносные линии от границ корпуса к размерной линии; **размерный текст в видимом небольшом боксе** с фоном и обводкой, читаемым при светлой/тёмной теме.
- Расположение линий адаптивно, минимизировать пересечения с корпусом, кабелями и друг с другом; в плотной сцене приоритет читаемости перед количеством линий.
- Учитывать viewport clipping, выбранные слои и camera transforms; не показывать текст вне экрана.
- `IgnorePointer` / выделенный `CustomPaint` + `RepaintBoundary`: линии не участвуют в hit-testing.
- Анимировать только alpha/opacity overlay, не перестраивать полную геометрию квартиры в 60 FPS от таймера.
- Показать реальные направления с единицами `мм`; никакой «электротехнической достоверности» от декоративной линии.
- Не допускать перекрытия портов/ручек кабеля кликабельным слоем.

## 7. Предлагаемые технические единицы (адаптировать к кодовой базе)

- `WallDistanceGuideCalculator` — **чистая функция** {component/footprint, room polygon, host, coordinate transforms} → immutable list of `DistanceGuide` {source boundary, wall hit, signed direction, lengthMm, status}.
- `DistanceGuideCoordinator` — selection/deselection, hold lifecycle, last-valid snapshot, cancellable delayed fade.
- `DynamicWallDimensionsOverlay` — отрисовка размерных линий и boxed text, независимый painter.
- `DistanceHoldButton` — pointer/keyboard press semantics, tool-bar integration.

Предпочтительно переиспользовать уже существующий `CadDimensionPainter` и camera projection, не создавать второй алгоритм стены/выбора объекта.

## 8. План реализации

**R0 — Architecture qualification:** подтвердить реальный источник footprint, трассировку выбранного компонента к помещению, existing `CadDimensionPainter`, отличие от `dimensionsVisible`; зафиксировать ограничения.

**R1 — Geometry:** чистый calculator, четыре направления для ортогональной комнаты, вогнутые/наклонные/нулевые случаи, цифровые golden tests.

**R2 — Overlay:** стрелки, выносные линии, boxed labels, clipping, reposition на zoom/pan, drag preview.

**R3 — Hold behavior:** кнопка Distance с настоящим DOWN/UP/CANCEL, клавиатурой, delays, disposal и reduced motion.

**R4 — Qualification:** widget/unit tests, full `flutter analyze`, `flutter test`, native macOS desktop visual UAT, доказательства отсутствия регрессий R4 device/cable workflow.
